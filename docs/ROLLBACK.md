# 一条指令回退：宿主执行完整流程

用户说“回退记忆系统”时，由已接入的智能体执行本流程。程序不能代替不存在的宿主API，CLI暂停与完整宿主回退应分别报告。

1. 调用`personal_bot --root <STATE> rollback`。即使SQLite已损坏，也先独立于数据库在配置锁内关闭enabled及七个feature，epoch围栏生效；数据库、后续新消息和快照保留。返回completed=false，说明原生动作尚未完成。
2. 从state/deployment.json及完整native-schedules导出找到实际本系统拥有的周期/runonce任务，原生工具停用并读回。不要误停邮件、无关任务或原QQ桥看门狗。未知交接不能自动补发；已经递送的消息不能撤回。
3. 停止/停用仅属于本系统的模型服务。保留依赖和模型文件作为恢复材料，不批量删目录。
4. 按安装时真实host_manifests的逆序恢复最小入口文件：只有当前哈希仍是本系统安装值时才还原原始字节；检测到他人修改就报告冲突，不强制覆盖。新文件也只移除已核验属于本系统安装的路径。
5. 根据保存的完整原生定义恢复恰好一代原有任务；不能启用所有归档任务，也不能恢复已完成runonce让其catch-up重发。若原环境本来没有这套任务，就维持停用。
6. 核验当前实际任务状态、旧聊天通路、代码/文件哈希、DB quick_check；分别报告已完成的本地暂停、文件恢复、原生调度恢复，以及任何仍需用户判断的冲突。

**完整数据恢复是另一件事。** 只能restore到新空目录，verify后relocate，确认匹配代码版本和新路径。还原后功能与蓝图停用；原生人格文件只是native/快照副本，不能不经核对覆盖现有宿主。激活新主机前先停旧主机相关工作者，防止两份状态同时发送。不要用旧DB覆盖之后的新聊天来回退代码。

完整快照包含实际引用的host_manifests和原始blob。relocate将清单引用重绑定到恢复目录，目标路径只指向隔离native副本，并保留original_host_path；再次备份仍保留原生文档树。把副本用于新的真实宿主前，必须重新核对并登记实时目标，不能执行旧绝对路径。代码版本不匹配时，先安装匹配版本；也可从快照的project/code启动其中保存的personal_bot。
