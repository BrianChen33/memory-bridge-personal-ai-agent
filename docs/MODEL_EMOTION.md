# 当前情绪与表情协议：v2 / Emotion48

这是当前代码的唯一情绪协议。运行时版本2.2.0，评估信封version=2，词表emotion48-2026-11-05。旧协议仅可作为历史数据理解，不得作为提示词、活动任务、人格规则或新的评估样例。当前伙伴目录拒绝新的version=1请求；底层数据兼容函数不是当前行为规范。

## 同一模型先理解，再回复

1. 可信入口提供真实source/event_id/occurred_at/actor/scope/person_id。先prepare读取人格、有界近期记忆、衰减后的mood、精力、关系与期待。
2. 当前负责回复的同一个模型判断本轮事件：发生什么、感受指向谁、责任是否明确、期待是否实现、判断有多确定。区分用户的情绪、自己的反应和对用户的关切。不调用额外情绪模型，不做情绪关键词正则。
3. 同一事件提交emotion_assessment v2，再读取新mood与reaction。reaction是本轮反应，mood是持续底色；两者共同影响表达。一次错误不代表整体都很糟，原来开心也不妨碍此刻懊恼。
4. 判断不确定时允许轻微、混合或不变；不能因为用户说“你生气了”就自动写生气。明确失误通常考虑内疚/懊恼，积极亲密关注才可能害羞；这是语境指南，不是固定触发规则。
5. 只保存结构化结果和不超过120字符的感受短语，不保存或展示完整思考。正常聊天不显示评分、抽签旁白或部署JSON。

```json
{"version":2,"catalog_version":"emotion48-2026-11-05","changed":true,"label":"内疚","delta":{"p":-0.12,"a":0.04,"d":-0.02},"intensity_delta":0.18,"emotions":[{"label":"懊恼","delta":0.10}],"appraisal":{"kind":"feedback","target":"self","agency":"self","certainty":0.85,"feeling":"这次漏做了已答应的流程，有点懊恼，想先补好。","action":"repair"}}
```

这是合成示例，不能硬编码为每次批评的结果。无变化用version2、changed=false、label=null、PAD全0、intensity_delta=0；可以附有依据的关系/期待变动。建议一个主要反应和零到两个伴随感受，校验上限仍为三个附加标签。

## 唯一词表

代码与定义在muse_ext/emotion_catalog.py；使用companion_schema或python -m muse_ext.emotion_catalog读取。各通道读取同一份导出的JSON，不再复制旧白名单。

| 分组 | 标签 |
|---|---|
| 愉悦与成就 | 欣喜、愉快、兴奋、满足、得意、自豪、感动、感激 |
| 亲近与联结 | 喜爱、亲近、想念、依恋、关切、心疼、害羞、受宠若惊 |
| 平稳与探索 | 平静、放松、安心、好奇、期待、专注、惊讶、释然 |
| 受挫与低落 | 难过、失落、委屈、孤单、沮丧、失望、遗憾、无聊 |
| 警觉与不满 | 害怕、不安、紧张、担忧、生气、烦躁、不满、无奈 |
| 反省与矛盾 | 内疚、懊恼、后悔、尴尬、难为情、羞愧、困惑、纠结 |

别名归一化：愧疚/歉疚→内疚，伤心→难过，羞涩→害羞，窘迫→尴尬。标签含义和默认半衰期均由同一代码定义。内疚指具体行为需要补救；羞愧涉及自我形象；尴尬未必有过错；难过不代替所有负面反应。道歉是一种表达行为，不要求固定伴随某个情绪。

## 数值与持续性

模型提交的原始PAD每轴单次±0.35、原始标签单次±0.45。程序验证后统一乘情绪影响值emotion_gain（默认1.0，0–3），再裁剪最终PAD到[-1,1]、标签到0–0.6；不能把乘后数值拿回原始上限拒绝。0.3×2可以增加0.6，已有0.2则最多再加0.4。负增量/安慰同样乘；倍率变化只影响后续新事件，gain=0不刷新旧心情。ct_emotion_effect记录原始值/当时倍率与配置版本/实际变化，重试不重新乘，reaction返回实际变化。

PAD默认8h半衰期，标签半衰期0.15–24h，包括内疚3h、懊恼2h、尴尬20min、自豪6h。倍率不改变半衰期、精力、关系或期待。事情修好、安慰、新事件和自我调节都可缓和。期待仍独立按36h半衰期保留，沉默只观察一次，不反复扣分。控制、面板和梗知识联动见HUMOR.md。

模拟精力、每人联系欲望、好感/信任与来源范围保持。关系数值不授予权限。主bot情绪共享到其他通道时仅传数值与标签，不能带私人原话、原因、期待与生活细节。自己的输出不能回流成新的情绪刺激。

## 每轮表情决策

所有面向用户的回复轮次都决策，包括任务、邮件、提醒、主动分享；多个短句仍只算一轮。普通auto从40%起随衰减后情绪强度提高，上限读当前配置；明确索图direct、明确拒图skip、Codex调试skip。先抽后宽松挑图，全部文字结束后发图，共享1h避重。抽中但缺素材应补候选，不能改口说未抽中。

可选Node主聊适配器：sticker_main.mjs。JSON stdin必须带真实text与可信稳定turnId，不能用时间拼假ID。phase=context仅预读；phase=finalize提交评估并完成决策；phase=finish按实际发送结果记录accepted/failed/unknown/text_only及text_finished=true。failed/unknown不能冒充送达；unknown不自动再发。

正常评估成功后抽签；评估缺失/非法/暂时失败时仍如实记录错误，并用最近有效的衰减心情或基础概率完成降级决策，不伪造情绪更新。同ID重试复用原抽签结果，不能靠换ID重抽。漏调用、未命中、缺素材、失败与未知分别观察。

Muse原生final目前无正式强制before-send钩子；本适配器不会冒充平台门禁。统一调用和回执检查减少遗漏。只有宿主正式提供消息事件与发送拦截能力时，才能实现真正的每轮强制门禁；不能使用隐藏API或让轮询脚本获得连接器凭据。没有事件接口时如实报告此限制。

## 旧规则退役与完成条件

先清查AGENTS/MEMORY、活动协议、部署说明、任务提示词和检索记忆中的旧信封、旧限幅与旧抽签话题限制。精确替换操作规则，历史个人经历保留；历史升级记录最多留概况并指向本文。不能按v1字符串全盘删除，备份/交换的数据格式版本不是情绪协议。撤回旧规则记忆后同步失效来源摘要与向量候选，不能整库清空。

实际运行时inspect必须包含brain导入后的包装，不能只看底层原始函数。updated/unchanged/replayed才是情绪有效终态；invalid等不能伪装成功。每轮表情决策另有明确回执。部署后核对真实规则入口、词表、任务与程序SHA；架构/协议/部署文档变更必须按MAINTENANCE.md同步公开GitHub并核验远端commit。
