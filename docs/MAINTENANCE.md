# 架构维护与 GitHub 同步

每次完善系统架构、程序、协议或部署说明，交付必须包含公开仓库同步和真实远端commit： https://github.com/BrianChen33/personal-ai-companion-kit 。只写本机文件、口头宣布已生效或生成安装包不算同步完成。

1. 以当前MODEL_EMOTION.md/运行时schema为唯一规范，删除活动入口里相冲突的旧提示词和部署说明。只保留不授予权限、不含执行旧协议步骤的历史概况；不要误删个人经历或其他模块的数据格式。
2. 将可复用代码与文档同步到公开仓库；真实人格、记忆、渠道标识、环境变量、登录态和密钥只留私有环境。通道适配发布通用接口，不发布某人的连接配置。
3. 更新包版本、provenance当前代码SHA、部署指南和继承说明。只做一次最终隔离验收，必要修正只验证相关点；不要向真人聊天/生产队列发合成探针，不新增回退工程。
4. 正常commit/push，读取远端分支SHA确认。权限/网络不支持时报告实际阻碍，不使用隐藏API或搬运其他电脑凭据。
5. 将线上版本与私有记忆库manifest的architecture commit锁同步。发布器按真实总结/初始化状态加代码commit去重，因此同一天升级后可提交新架构快照，无须删除旧回执或强推历史。
6. 最后报告实际启用版本、远端commit、规则清理范围、宿主限制和仍未完成的项目。不能用代码可解析某协议代替主聊提示词/真实工具接线完成。

日常情绪数值、日记、关系与生活事件变化不属于架构改动，走既定私库每日备份，避免每轮聊天产生代码提交。
