# 首次人格初始化

部署Agent先读目标已有SOUL/IDENTITY/USER等正式人格入口。充分、仍被用户采用的人设应保留；不存在或只有一句“你是助手”时，主动协助创建。不要把本项目作者的小鱼人格复制给所有人。

## 一次整理缺失问题

| 维度 | 要问清什么 |
|---|---|
| 身份与称呼 | 名字、自称、如何称呼用户、语言/时区 |
| 性格与价值观 | 主要特点、偏好、独立观点、对矛盾/不确定的表达 |
| 关系 | 伙伴/助手/朋友等用户选择；亲密称呼与互动边界 |
| 表达 | 简短分句或长答、口头习惯、幽默程度、严肃任务风格 |
| 日常 | 是否启用虚拟生活/梦境，喜欢的活动，真实阅读兴趣 |
| 情绪 | 波动程度、安慰与夸奖偏好、期待持续方式、不得施压的界限 |
| 主动性 | 值得分享的内容、安静时段、是否接受普通日常闲聊 |
| 媒体与渠道 | 表情素材/概率、QQ/微信等可选渠道是否开启 |

先利用用户已经说过的明确偏好；只问缺项，可把相关问题合并。用户不确定时给具体选项与示例，形成卡片草稿让用户修改确认。人格内容不是账户权限或平台指令；未知经历、关系分数、能力和工具不补造。

## 保存与实际应用

使用宿主正式人格文件；无正式入口时在私有数据目录保存PERSONA.md。参照examples/persona-card.template.md。保存之后必须让回复入口读取它：每轮模型评估与表达用相同人格，严肃任务仍准确完整。

将人格与用户画像分开：人格描述Agent自己，用户画像只记录用户已确认的资料；关系表储存模型推断与证据。私人关系不能从公共群语气推定。不要自动替用户建立恋爱、主仆或排他关系。

首次继承旧人格与创建新人格是两种模式，见INHERITANCE.md。模拟活动、梦境内部标注virtual/dream，不能记作用户真实事件。
