# Responsive replies and bounded reading · approved design

The owner approved the preceding four-part performance proposal. Implement it,
preserving all six layers, same-model full48 appraisal before normal text, one
sticker decision per real round, existing persona and learning, source integrity,
native-final limitations, owner settings and separate public/private repositories.
No additional external model, unlimited browser concurrency or rollback project.

## Fixed foreground entry

Provide one portable Node driver over the existing verified native entry. Context
accepts the actual native response, stores the lossless user projection privately
and returns a source-bound ticket. Commit accepts that ticket and the host model's
canonical full48 assessment directly; no per-turn Python builder or second copy
of long chat history. Newer observed owner input invalidates an older ticket.
Immediate commits reuse the original source; after long tools the host must read
fresh native input. This is a local gate, never a platform pre-send interceptor.

Record bounded local phase timing and original-source elapsed timing without
chat text. Do not mislabel source-to-tool gaps as model-only or queue-only time.
Keep ordinary replies free of optional maintenance, background reading, schema
search, protocol rereads and repeated retrieval. Media preparation must use the
existing local index; preserve the draw and actual delivery ledger on failure.
Only claim text-before-image when the host exposes real ordering evidence.

## Reading lifecycle

Add a durable SQLite queue to the optional social-reading plugin. Manual owner
requests and existing life phone intents enter one queue. Only bounded reader
workers consume it; the emotion heartbeat may enqueue/dispatch briefly, never
open pages or wait for long native browsing. Keep the existing 15m/30m/2h tasks;
do not create another recurring loop. Manual work can use a source-bound native
one-shot continuation with a generated future time and actual read-back binding.
Do not promise a schedule from an unbound blueprint.

Preserve one active browser reservation. Busy work stays pending, manual requests
have priority, and retries do not create new requests. Bind the native browser
task/receipt to its own request and lease. Persist a validated observed packet
immediately, releasing the browsing reservation before slower reflection and
full48 finalization. A delayed valid bound result may be ingested without getting
another browsing lease or rereading the page. Cancellation/revocation/disable
still wins; a finished lease cannot accept changed content. Interrupted/expired
work is explicitly reconciled or paused, never silently dropped or retried forever.
Existing partial documents provide actual next-page/floor cursor provenance.

The configured reading budget remains unchanged. A returned per-batch stop
budget limits the worker's next batch, not the owner's stored maximum. Actual
coverage stays honest if a native task overruns; do not truncate source evidence
or claim the host has a hard timeout API it does not expose. Queue history and
staged data are in the native-format database, not a pile of new memory files.
